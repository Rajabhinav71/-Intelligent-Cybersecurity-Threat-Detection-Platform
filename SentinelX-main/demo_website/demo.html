How SentinelX works

Every HTTP request passes through these layers in order. Here's what happens step by step.

1 — HTTP request arrives
User submits login form → browser sends POST /api/auth/login
↓
2 — SentinelFilter (first gate)
Runs before any controller. Checks: Is IP blocked? Scan for SQLi/XSS/path traversal. Block scanner user-agents. Count requests (rate limit).
SentinelFilter.java
If threat found → return HTTP 403 immediately. Controller never runs.
↓
3 — AuthController receives request
Checks credentials against user database. Saves the login event (success or failure) to MySQL.
AuthController.java LoginEvent.java
↓
4 — DetectionService analyses
Runs 4 rules: brute force by user, credential stuffing, brute force by IP, rate limit. Then calls Python ML service for anomaly score. Returns risk score 0–100.
DetectionService.java model.py (Python)
↓
5 — ActionService responds
Score ≥ 80 → block IP or lock account. Score ≥ 50 → create alert. Saves ThreatAlert to DB.
ActionService.java ThreatAlert.java
↓
6 — Dashboard updates
DashboardController serves /api/dashboard/* endpoints. The HTML dashboard polls every 5 seconds and shows live threat data.
DashboardController.java index.html
Detection rules explained
Brute force rule
Count failed logins for username OR from IP in the last 5 minutes. If ≥ 5 failures → risk score 90, lock account.
Credential stuffing rule
Count distinct usernames tried from same IP in 5 minutes. If ≥ 10 different usernames → risk score 85, block IP.
Rate limit rule
In-memory counter per IP, resets every minute. If > 100 requests/min → risk score 75.
Injection scan (SentinelFilter)
Regex patterns scan all request parameters BEFORE the controller runs. Catches SQLi, XSS, path traversal. Returns 403 instantly.
ML anomaly detection
Isolation Forest trained on normal behaviour. Features: failed_logins, request_rate, hour_of_day, login_success. Returns anomaly score 0–100.
Risk score → action mapping
Score ≥ 80 Block IP (24 hrs) or lock account immediately
Score 50–79 Create alert — shown on dashboard, no block yet
Score 0–49 Normal — request passes through
